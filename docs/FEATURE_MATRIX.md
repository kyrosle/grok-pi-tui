# Pi Core + Grok Build-style Native TUI Feature Matrix

Master transition: [SPEC](issues/架构/20261003-pi-native-tui-SPEC.md) / [PLAN](issues/架构/20261003-pi-native-tui-PLAN.md). T0 replaces reference byte identity with architecture guards; T1 closes remaining entries. Compiled removal debt and T2–T8 remain explicit. Current capabilities below are checkpoints, not completion of END-01–09.



**Minimum Pi version: 1.0.0** (system `pi` / `@earendil-works/pi-coding-agent`). `pi-main` is an optional git submodule, not required at runtime.

Status definitions: **Native** = implemented by a Grok Pager component; **Adapted** = Pi semantics converted and projected into a Grok native component; **Boundary** = Pi RPC does not expose it or it is bound to a Grok product backend, deliberately not implemented. **Bundled extension** identifies grok-pi additions using Pi APIs rather than Pi built-ins.

Current scope follows the [product-surface SPEC](issues/架构/20261003-pi-product-surface-SPEC.md) and [PLAN](issues/架构/20261003-pi-product-surface-PLAN.md). Pi owns models/providers/authentication, tools, sessions, retry and compaction; Pager supplies the native terminal UI. Queue interception, adapter Plan/Goal state and optional Rhai orchestration remain recorded ownership debts. Grok voice/STT/TTS and stock account/billing/training/retention/agent/plugin/MCP controls are excluded from the external surface; F2, palette and Web host settings share the filtered catalog.

Published binary: **v0.1.10, macOS 14+ Apple Silicon only**; `pig` is the short entry. The archive includes relocated non-system dylibs. Intel/Linux/Windows artifacts are not published yet. See the [release record](issues/grok-pi/20261005-v0.1.10-macos-release.md).

## Agent and Streaming Semantics

| Pi feature | Status | Mapping |
|---|---|---|
| Prompt | Adapted | ACP prompt → Pi `prompt` |
| Mid-turn send now | Adapted | Composer send-now → locally held `Steering` lane row (same isolated queue as follow-ups), forwarded to Pi as `steer` at the assistant `message_end` safe-point flush; the row stays removable/editable until then; rows still held at settle dispatch as the next turn's prompt. A pending row can also be sent immediately via `x.ai/queue/interject`; edit-then-send uses the row version. Rows discovered only in Pi's external queue remain read-only because stock RPC cannot remove them atomically. |
| Follow-up queue | Adapted | Active-turn client prompts and extension `sendUserMessage(..., { deliverAs: "followUp" })` calls stay in an adapter-owned isolated queue until dispatch; extension steers (`deliverAs: "steer"`) are held in the same isolated queue's steering lane instead of interjecting immediately. Promoted rows re-enter Pi with RPC source; `queue_update` messages that bypass interception are mirrored in a separate external lane. |
| Abort | Adapted+Boundary | ACP cancel synchronously clears adapter-owned client/extension rows and completes their waiters, drops extension continuations emitted while cancellation is active, then fire-and-forget notifies Pi `abort` (`abort_bash` for Bash). A `get_state` settle probe reopens dispatch only after Pi is idle. Pi 1.0 `clear_queue` is sent before both abort paths to clear external rows; cancellation continuations repeat that ordering. |
| Text stream | Adapted | `message_update` → AgentMessageChunk |
| Thinking/reasoning stream | Adapted | `message_update` → AgentThoughtChunk |
| Tool start/update/end | Adapted | ACP `ToolCall`/`ToolCallUpdate` |
| Pi Codemode rendering | Native+Adapted | Opt-in (F2 `pi_builtin_tools.codemode`) loads Pi's `builtin:codemode` extension. The adapter tags `raw_input.variant="Codemode"`, projects a canonical `Codemode` raw output (nested call records, header-stripped script output, spilled full-output path) and suppresses native rows for nested calls carrying a codemode `parentToolCallId`, so live sessions and replay render the same dedicated `CodemodeToolCallBlock` (script highlight, nested-call list with status/duration/cost, output preview). See `docs/issues/adapter/20260930-Codemode-原生渲染支持.md`. |
| Eval v2 host-tool bridge | Adapted | `pi-grok-bash` owns the Node/Python Eval worker, `HostCallGate` (cap 4), `EvalSessionToolBridge`, explicit `store/load`, `parallel/pipeline`, and native task projection; Eval remains a nested Pi capability rather than a second agent core. Cells that never call a host tool always render as a normal Eval card regardless of the effects-first setting or Eval-v2-only hiding (`details.toolCalls` in the result drives the decision; legacy payloads keep the old behavior) |
| Eval v2-only MCP facade | Adapted+Boundary | Opt-in authenticated loopback Streamable HTTP lets an external MCP client call the live Eval v2 session; binding IDs/secrets, resource images, tokenizer accounting, and shutdown are owned by `eval-pi-mcp`, not Pi's outbound MCP client |
| Pi Codemode/MCP reuse from Eval v2 | Adapted+Boundary | F2 `pi_mcp` is default off and explicitly loads Pi 1.0 built-in MCP, Codemode and tool search. Pi owns connection, trust, exposure and OAuth. Eval calls callable tools through `ctx.executeTool`; `await tools.waitFor(pattern, timeout_ms)` observes the public registry while async servers connect. Hidden tools and CLI exclusions remain enforced; model-only orchestration tools cannot be nested-called. The explicit external Eval MCP facade retains its off-turn compatibility boundary. |
| Pi Bash background task / Send to Background | Native+Adapted | `grok-pi` private Bash extension holds foreground and initial background Bash subprocesses; foreground reuses Pi `createBashToolDefinition` output/rendering semantics. Pager native Send to Background transfers control via `x.ai/terminal/background` using a controlled temp file keyed by `toolCallId` to the **same** subprocess, then projects to the existing `x.ai/task_*` card; native task-card kill uses `x.ai/task/kill` over the same control channel (`op:kill` + published `runningTaskIds`); `is_background` + `description`, `get_task_output` / `wait_tasks` / `kill_task` remain usable. Foreground Bash auto-promotes after the shared configurable max-wait threshold (default 4.5 min), and each blocking task wait is capped to the same threshold so a still-running task yields a fresh agent turn instead of holding the prompt cache past TTL. `0`/negative disables both behaviors. Terminal state is published out of band on the private `__pi_grok_bash_task__` status channel so it survives streaming, ESC, and a cleared follow-up queue; the conversation bridge message still wakes the model. The adapter mirrors task lifetime, projects each terminal state exactly once across both channels, and settles tasks orphaned by a Pi child exit as `signal: session_restart` (row leaves the running filter, no new failure block). |
| Pi subagents | Bundled extension+Native | F2 `[ui].pi_subagents` is default on and restart-required. V1 uses Pi child `AgentSession`, native `SubagentBlock`/Tasks Pane/child `AgentView` projection, product-isolated `.grok-pi/agents/*.md` + `~/.grok-pi/agents/*.md` definitions, history/wait/cancel, and parent→child follow-up/steer. Optional V2 (F2 → Agent → "Pi subagents V2", or `PI_GROK_SUBAGENTS_V2=1`) adds Codex-inspired `/root/...` paths that are stable within the current root Pi session, plus `spawn_team_agent`, queue-only `team_send_message`, triggering `team_followup_task`, `team_wait`, `team_list`, `team_interrupt`, nested spawn, and automatic `FINAL_ANSWER` return to the parent. `spawn_team` loads project `.grok-pi/teams/*.json` > global `~/.grok-pi/teams/*.json` > bundled `research`/`implementation`/`review` presets. V2 semantic messages use `pi-grok-team-message/v2`; all UI-only `pi-grok-subagent/v1` lifecycle and child updates use one process-private ordered socket, whose readiness is required before child startup. Low-frequency recovery snapshots live in `<parent-session>.subagents.jsonl`; `session/load` explicitly replays them after the root barrier and waits for a request-scoped socket `replay_complete` marker, and neither bridge nor snapshot entries are appended to the parent Pi JSONL. Completed agents become `IDLE`; reactivation preserves the underlying Pi child session but rotates the Pager child/run identity and stores leaf boundaries so each run restores only its own transcript. Background concurrency is capped at 4 with cancellation-safe queueing and atomic preset startup. Product guide: `docs/usage/subagents-v2.md`. Model-driven end-to-end acceptance remains pending. |
| Workflow (Rhai / `/workflow`) | Optional upstream engine + Pi spawn seam | **Default off; session host + slash surface:** reuses `xai-workflow` + `ExternalWorkflowRuntime`; adapter `x.ai/workflow/{launch,pause,stop}` + `x.ai/workflows/list` + `workflow_updated`; injects `/workflow`, `/workflows`, `/create-workflow` (+ named scripts); hides `__pi_workflow_*` bridge cmds; Pager local handlers + F2 gate. `/create-workflow` is Pager PassThrough user prompt (not a Pi skill). | Retry | Adapted | Grok native sticky status/toast |
| RPC connection resilience | Adapted | Unexpected Pi RPC child exit triggers automatic respawn with backoff (storm guard: max 3 recoveries per 5 min), fresh bootstrap, and `switch_session` reattach of the pre-crash session file; deliberate teardowns (probes, respawn) carry `intentional` and are skipped. | Session recap (`/recap` + auto away) | Adapted | initialize `meta.sessionRecap`; `x.ai/recap` → inject extension `__pi_grok_recap` (called on `complete` side, appends a non-context custom entry via `appendEntry`, so summaries never enter the agent loop context; legacy sendMessage-era custom messages are stripped from LLM context by the extension's `context` hook) → custom entry `pi-grok-recap/v1` (`entry_appended`) → `SessionRecap`. | BTW history (`/btw` + `/btw-history`) | Adapted | Live deltas/answers stream through `appendEntry("pi-grok-btw/v1", …)` custom entries — never `sendMessage`, so bridge traffic never enters the agent loop context (legacy sendMessage-era custom messages are stripped from LLM context by the extension's `context` hook). | Queue pane / count | Adapted+Boundary | Adapter-owned client/extension rows — including mid-turn steer rows — support real remove, clear, edit, reorder, and interject operations before dispatch, so a queued steer is cancellable until its safe-point forward. Stable ids and versions preserve Pager reconciliation and original display text. Pi `queue_update` still feeds a read-only external lane for messages that bypass interception; only follow-up dequeue advances `runningPromptId`, while steering remains in the current turn. Pi drain mode remains settable via `pi/queue/mode` (`one-at-a-time` / `all`) for its own queue; locally held follow-ups still dispatch one by one as ordinary prompts. This ownership has not migrated to Pi. |
| Context bar used tokens | Adapted | Pi `contextUsage` / message usage → ACP `_meta.totalTokens` → top-right bar |
| Context click / `/context` | Native+Adapted | Grok `x.ai/session/info` → Pi stats + messages + `__pi_context_breakdown` + optional `cacheMetrics` (from `get_entries`, pi-cache-graph formula) → native `ModalWindow` (`ContextInfoBlock` + views `0/1/2/3/s`, `e` export, `r` refresh); F2 `[ui].pi_cache_graph` default on; live refresh while running, not written to scrollback |
| User prompt markdown (grok-pi) | Native | F2 `[ui].pi_user_markdown` default on; collapsed/truncated prompts keep the native 3-line `UserPromptBlock` preview, while expanding renders the body with agent Markdown and preserves user chrome. ## Slash Commands

### Retained Grok Native Commands

`exit`, `help`, `hotkeys` (aliases `shortcuts`/`keys`), `tutorial` (aliases `tour`/`onboarding`), `new`, `compact`, `model`, `effort`, `rename`, `resume`, `session-info` (alias `session`), `tree`, `tree-map`, `fork`, `clone`, `reload`, `pi-runtime`, `notify`, `dashboard`, `recap`, `btw`, `copy`, `find`, `jump`, `review-session`, `review-message`, `transcript`, `export`, `expand`, `queue`, `plan`, `plan-mode`, `view-plan`, `multiline`, `compact-mode`, `eval-display`, `vim-mode`, `theme`, `timestamps`, `timeline`, `toggle-mouse-reporting`, `doctor`, `debug`, `pi-config`, `pi-models`, `pi-shortcut-manager`. Individual visibility/capability gates still apply. When F2 `pi_btw` is enabled, the Pi extension also advertises `/btw-history` as a direct, model-free history view.

### Dynamic Pi Commands

Extension, Prompt Template, and Skill commands returned by Pi are not hard-coded in Rust. They enter the Grok native slash suggestion/dropdown through the ACP command catalog; name conflicts are de-duplicated by the Grok registry. Built-in bridge extensions can also add Pi-provider auth (`/login`, `/logout`), Pi HTML export/share (`/export-html`, `/pi-share`) and F2-gated workflow/automation commands.

### Deliberately Excluded

Grok voice/STT/TTS has no command, shortcut or settings entry in grok-pi. Stock Grok product or local session-store commands—including `/voice`, Grok `/history`, Grok account `/login`/`/logout`, `usage`, `plugins`, `mcp`, `memory`, `workspace`, and `share`—are excluded. The same bare `/login`/`/logout` names may be supplied by grok-pi's Pi auth extension, where they authenticate Pi model providers rather than Grok.com. The original `/minimal` and `/fullscreen` re-exec commands are also not exposed: switch screen mode at startup so Pi process arguments are preserved.

## Current Pi authentication ownership

The login/logout bridge delegates Pi ModelRuntime and only maps provider/method selection, prompts, notifications and UI responses. Generic Radius login remains; the bridge neither confirms nor writes Radius MCP configuration or mcp.json. MCP configuration uses Pi-supported entry points. Development acceptance is the native bridge contract/lifecycle; real Pi/provider flows remain supplementary pending experience.
