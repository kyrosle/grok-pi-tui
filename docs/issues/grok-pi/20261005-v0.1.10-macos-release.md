## 已发现边界

原 release workflow 使用默认 features，会混入 stock runtime；改为明确的 `--no-default-features --features release-dist,jemalloc,sandbox-enforce`。更新器仍访问 `Dwsy/grok-pi` 并回退到其 npm 包，须随本 fork 切换，不能下载另一个产品。当前 Mac release 依赖 `/opt/local/lib/libiconv.2.dylib` 和 `libz.1.dylib`；发布包必须包含并重定位非系统动态库。

本次是指定版本的平台交付，不代表总体 native TUI SPEC 的 T2–T8 完成。真人 OAuth、provider 推理和其他 Mac/终端独立验收。

## 发布约定

每个正式版本必须有双语 Changelog 对应段、独立 `vX.Y.Z` tag、`GROK_PI_VERSION=X.Y.Z` 构建和同 tag 的 GitHub Release。二进制源码提交对应 tag；后续交付证据作为文档提交追加，不移动 tag。当前 macOS 使用 release-dist / CGU16 / LTO off / debug0 和生产 features；打包命令 `python3 scripts/package-macos.py target/release-dist/grok-pi dist/vX.Y.Z/grok-pi-macos-aarch64.tar.gz`。当前源码发布之外的架构工作保持原 PLAN。

复用 GitHub Actions 手动 `workflow_dispatch` 可重建已有 tag 的 macOS arm64 包；tag push 不自动发起多平台构建，避免替换本次指定的本机 build。发布库为 libiconv 1.17 与 zlib 1.3.1，附源码与许可证。
